# LikeBox 同步与数据一致性

本文说明电脑（`LikeBox.exe`）与手机（Termux）两端如何保持一致，以及为什么两端同时读写也不会互相覆盖。

## 1. 拓扑：一端服务端，一端客户端

- 服务端（通常是电脑）：`role=server`，提供 `POST /api/sync/merge`，监听 `0.0.0.0:8180`。
- 客户端（通常是手机）：`role=client`，后台线程每 8 秒向 `peer_url` 调用一次 merge；失败 10 秒后重试。
- 两端各自持有完整的 SQLite 文件，**任何一方都不会把数据库文件覆盖到对方**。同步走的是记录级的数据交换，不是文件同步。

## 2. 不做整库覆盖，只做记录级合并

整库覆盖是数据丢失的根源：一端稍旧的文件覆盖另一端，对方的新增就没了解释。LikeBox 的做法是：

- 只同步主收藏夹的 `folders`、`bookmarks`、`excluded`（排除域名）。
- 不同步：数据库文件、打开统计、界面设置、同步配置本身。
- 每条记录按**业务键**匹配，而不是按自增 ID（两端 ID 空间互不相干）：
  - 书签：`url` + 所属文件夹路径
  - 文件夹：完整路径（父子链）
  - 排除域名：域名本身

## 3. 变更检测：hash + version

每条记录计算内容 hash 和版本号 `version = max(updated_at, created_at, add_date)`：

- 两端各维护 `sync_state` 表，保存上一次同步后每条记录的 `hash` 与 `version`。
- 每次 merge 只发送「hash 变了或 version 变大」的实体，其余跳过。
- 接收方按业务键 upsert：同一业务键已存在就就地更新，不存在才插入。**重复推送不会产生副本**，同一批数据推多少次，结果都一样。

## 4. 删除也要同步：墓碑表

只同步「存在」的记录是不够的——A 端删掉一条，B 端仍持有它，下一轮 B 端会把它当成「新增」推回来，删除等于失效。

因此删除写入 `sync_tombstones`（业务键 + 删除时刻），随 merge 一起传播：接收方看到墓碑就删除对应记录，并记录该业务键已被删除，之后不再把它推回去。

## 5. 冲突：后写优先，平局服务端优先

两端同时改同一条记录时，按 `version` 比较，大的赢（后写优先）。`version` 相同（例如两边在同一秒各改一次）时服务端优先。结果确定、可预期，不会出现两端反复互相覆盖的死循环。

代价是：平局时客户端的改动会被服务端的版本取代。要彻底避免，需要在记录级保留改动意图，这属于后续工作。

## 6. 身份与鉴权

- 每端有独立 `device_id`，merge 时校验，防止一端把自己当对端同步（会造成自我覆盖和状态错乱）。
- 接口要求 `X-LikeBox-Sync-Token` 请求头，服务端用常量时间比较，避免时序侧信道。令牌只存在本地数据库，不进代码、不进 Git。
- 同步接口是 token 白名单，不依赖网页登录密码；网页其余接口仍走 `/login`。

## 7. 断线降级：本地永远可写

对端不可达时，客户端只写 `last_error`，本地读写完全不受影响，不进入任何「等待同步」的阻塞状态。恢复连通后，`sync_state` 里仍是上次同步的基线，本轮会把断线期间所有变更一次性推过去——**离线期间的操作不会丢**。

服务端同理：对方不在线时它照常服务本机页面，等对方回来再合并。

## 8. 数据安全网：定时一致快照

`sqlite3.backup()` 做在线一致性快照（不会拿到写了一半的库），快照后跑 `PRAGMA integrity_check` 校验，保留最近 3 份，间隔 2 小时。备份位置在数据目录下的 `backups/`。

## 9. 一致性怎么验证

两端各自算出内容指纹（对排序后的业务键 + hash 求摘要）：

- 指纹相同 = 两端内容逐条一致。
- 指纹不同 = 还有未合并的差异，先看 `last_error`、再看 merge 返回的计数。

2026-11-26 的收敛实测：以手机库为基线重建电脑库后，两端均为 365 条书签 / 12 个文件夹，指纹 `5b1d627f2009d3cb`；随后做双向冒烟——手机新增一条，16 秒内电脑可见；手机删除，16 秒内电脑消失；两端指纹回到同一值，无残留。

## 10. 已知边界

- 只同步主收藏夹，其他收藏夹（多库）各自独立，不跨端。
- 不支持同一时刻两端对同一业务键的语义合并（只能一方胜出）。
- `peer_url` 是单一地址，网段变化（例如 USB 共享从 `192.168.52.x` 换到 `192.168.226.x`）需要手工改配置。
- 桌面版的数据目录跟着 exe 走（`<exe目录>/data`）。**把 exe 复制到别处运行会产生第二份独立数据库**，这是最容易制造分叉的操作，应避免。
- 每笔操作的审计日志（audit）与断线重放队列尚未实现，当前依赖「快照 + 增量合并」兜底。
